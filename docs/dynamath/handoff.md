## 1. 출발점 — 기존 TeleNeuron과 다른 핵심 철학

기존 Endophalon 실험은 입자·스프링·충돌·다중 적분으로 비선형 물리계를 구성하고 정보를 읽어냈다. 이번에는 **물리계를 추상화**한다. 실제 물체, 3D 거리, 질량, 스프링, 충돌, 힘 적분은 **DynaMath 1 런타임에 존재하면 안 된다**. ‘물리계’라는 개념에서 상태가 지속되고 외부 교란에 반응하며 규칙에 따라 변화한다는 성질만 남긴다.

공간은 **정보 주소(address)를 갖는 값들의 집합**이다. 주소는 반드시 유클리드 공간의 위치일 필요가 없으며, 연결이 있다면 정보 상호작용의 의미로 사용한다.

- 시스템 실행 시 고정된 수학 법칙에 따라 상태가 **매 틱 1회** 갱신된다. 입력이 없어도 실행 중이면 틱이 흐르고 상태가 갱신된다.
- 외부 입력은 명령 실행이 아니라, 해당 입력에 매핑된 **하나 이상 정보 주소의 현재 값에 정해진 크기를 덧셈**하는 사건이다. 덮어쓰기나 전체 초기화는 기본 입력 메커니즘이 아니다. 부호 있는 증분을 허용한다.
- **입력과 출력이 없어도 내부 동역학은 지속**된다. 출력 시점에도 현재 상태를 보존하며, 다음 틱은 그 상태에서 이어진다. 출력 후 상태를 초기화하지 않는다.
- **출력도 정보 주소에 대응**한다. 지정 주소의 값이 조건을 충족하면 특정 토큰/행동/이벤트를 출력한다. 값이 특정 실수와 정확히 같은지(`==`) 비교하지 말고, 임계값 통과·히스테리시스·불응기 등 안정적인 이벤트 감지 정책을 정한다. 이 정책의 비학습성/학습성은 명확히 기록한다.
- 외부로 출력한 토큰을 필요에 따라 지정 입력 주소에 **덧셈으로 되먹임**해 문장을 이어 생성할 수 있다. 출력 이벤트가 내부 상태를 소거하는 방식은 금지한다.

## 2. 절대 공식 다섯 개 — 반드시 보존할 동작 규약

공식 5개를 학습하고 **하나의 공유 상태에 순환적으로 적용**한다. 각 공식은 고정된 코드로 따로 명령을 실행하는 하드코딩 규칙이 아니라 **학습 가능한 수학적 전이 법칙**이다. 추론 중 공식의 파라미터는 고정되지만 상태는 계속 변한다.

- 공유 상태 `S_t ∈ R^N` (N은 Work가 결정)
- 입력 증분 벡터 `I_t ∈ R^N`, 대응 주소 외에는 0
- 공식 `F_0, F_1, F_2, F_3, F_4`
- 1틱 동작: `S'_t = S_t + I_t` → `S_{t+1} = F_{t mod 5}(S'_t)` → 출력 주소 이벤트 검사 → 상태를 그대로 다음 틱으로 넘김
- 공식 순서: `F0 → F1 → F2 → F3 → F4 → F0 → ...`
- 실제 출력 검사 시점과 입력 큐 적용 타이밍은 하나의 결정적 규약으로 문서화해야 한다. 틱/단계(phase)는 체크포인트와 재현성에 포함한다.
- **학습의 주 대상은 다섯 공식 자체**다. 초기 상태값은 학습된 지식의 저장소가 아니다. 초기 상태는 기본적으로 0 등의 중립값으로 정하고, 필요한 경우 명시적 시드 기반 초기화 옵션만 둔다. 학습할 수 있는 것은 공식의 구조/계수이며, 부가적인 학습 가능한 대형 임베딩·Transformer·별도 언어모델·거대한 MLP 헤드를 몰래 끼워 넣어 성능을 만들어내지 않는다. 고정 입력 인코더와 출력 주소 맵을 우선한다. 선택한 공식 구조가 학습 가능한 계수식인지 기호식 구조 탐색을 포함하는지 구별해 기록한다.
- 공식마다 저랭크/희소/국소 상호작용 등 연산량이 작은 구조를 우선 검토한다. 하지만 안정적 기억·비선형 계산이 가능해야 하며, 단순 주소별 독립 업데이트만으로 끝내지 않는다.

**반드시 답할 설계 질문:** 모든 공식의 계수는 별도인가? 정보 주소 사이의 상호작용은 어떻게 생기는가? 5단계 주기의 위상 민감도를 어떻게 처리하는가? 입력이 없을 때 상태가 무의미하게 수렴/발산하지 않는가? 연속 입력에 대한 기억과 안정성을 어떻게 확보하는가? 출력 임계값을 학습 손실과 어떻게 연결하는가?

## 3. 챗봇으로 연결되는 최소 구조

첫 목표는 GPT-2급 언어 품질이 **아니다**. 그러나 '챗봇을 만들 수 있는 아키텍처'라는 목적에 맞게 **실제 생성 경로**를 구현해야 한다.

- 입력 메시지→문자 또는 작은 토큰 집합→해당 입력 주소에 **가산 주입**
- 동역학 반복→출력 주소의 값으로 토큰 선택/출력 이벤트 판단→상태 유지→다음 토큰 진행
- 사용자 입력이 없을 때도 동역학은 계속 실행 가능하되 CPU 낭비를 방지하기 위한 `tick(n)` 배치 실행과 선택적 실시간 루프를 구별한다. **실행 중에만** 틱이 진행되며, 프로세스가 꺼졌는데도 계산된다고 주장하지 않는다.
- 출력 토큰의 되먹임이 필요하면 동일한 가산 입력 경로를 이용한다.
- CLI에서 입력하고 실제 출력 문자열을 보는 **작동하는 최소 챗봇/문자 생성 데모**를 포함한다. 고정 응답 문자열을 분기해 출력하는 가짜 챗봇은 금지한다. 충분한 학습 데이터와 표현력이 없으면 결과가 유치하거나 무의미해도 그대로 보고한다.
- 안전한 종료·최대 틱·최대 생성 길이·출력이 없는 상황·동시 임계값 발동·반복 발동 처리 규칙을 정의한다.

## 4. Work가 자체 확정할 학습 및 아키텍처

공식 형태는 Work가 결정한다. 비교 대상으로는 다음 정도를 고려할 수 있으나 필수 채택은 아니다.

`F_k(S) = (1 - α_k) S + α_k tanh(D_k S + U_k (V_kᵀ S) + b_k)`

대각선 `D_k` 및 낮은 랭크의 `U_k,V_k`는 매 틱의 복잡도를 `O(Nr)` 수준으로 제어하는 후보일 뿐이다. 정보 주소 출력 방식과 충돌하지 않도록 설계한다.

- 학습 대상: 5개 공식의 파라미터. BPTT/TBPTT, 미분 가능한 전이 학습, 또는 더 효율적인 방법 중 합리적인 것을 택한다.
- 학습은 재현 가능해야 한다. 시드, 데이터 분할, 하이퍼파라미터, 실행 명령, 체크포인트와 모델 로드/재개를 문서화한다.
- 출력 주소 조건만으로 학습이 불안정하다면, **출력 주소의 연속값을 학습 손실에서 직접 사용**하되 실제 추론의 출력은 명세한 주소 기반 이벤트로 유지하는 설계를 검토한다.
- 검증 때 정답 정보를 입력하거나, inference에서 정답/템플릿을 유출하는 우회 구현 금지.
- 수학적 안정성(폭주, 소실, 포화, 기억 파괴), 위상 의존성, 출력 반복 폭주를 확인한다.

## 5. 첫 실험 — 작지만 정직하고 반복 가능한 검증

가장 작은 실험으로 **실제로 학습되고 상태가 유지되는지** 입증한다. 불필요하게 큰 탐색/수백 실험을 수행하지 말고, 명확한 기준으로 진행하라.

**필수 최소 실험:**
1. **동역학 단위 실험:** 5개 공식 순서·입력 주소 가산·출력 후 상태 유지·무입력 틱 진행·저장/로드 후 상태/phase 재현성 확인.
2. **기억 + 비선형 계산:** XOR 또는 패리티 같은 비선형 과제 1개와 `recall1` 또는 짧은 지연 재현 과제 1개에서 학습 전후 및 홀드아웃 성능 확인. 단일 공식이나 간단한 선형 기준선과 가벼운 비교가 가능하면 수행.
3. **최소 문자 생성:** 자체 입력/출력 주소를 갖는 작은 말뭉치로 문자/토큰 생성 경로를 실제 학습해 CLI 데모로 실행. 훈련 문자열의 하드코딩 재생은 불허. 훈련/홀드아웃을 구별하고 생성 결과 몇 개를 그대로 기록.
4. **연산량:** 틱당 파라미터 수, 근사 연산 복잡도, CPU에서의 실제 틱/초 및 생성 속도/메모리 측정. 기존 스프링 144노드·506스프링·2서브스텝·16스텝과의 비교를 한다면 동일한 측정 조건과 비교 단위를 명확히 밝혀라. 마이크로벤치 속도를 전체 챗봇 속도로 둔갑시키지 말 것.

**판정:** 구현이 실행되고 학습 손실이 변화하는 것과 과제의 홀드아웃 성능은 별개다. 실패·부분 성공을 그대로 기록하라. GPT-2 수준을 입증했다고 주장하지 않는다. Work가 설정한 1차 합격 기준과 실제 달성 여부를 분리해 기록한다.
